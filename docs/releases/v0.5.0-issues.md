## 2. Fix: telemetry hygiene defects found during v0.5.0 design

**Labels:** `bug`, `security`, `observability` · **Depends on:** none

Defects that exist today, independent of new telemetry:
- `agent_request_validation_failed` (`api/main.py:327`) logs `exc.errors()`, whose
  entries include the rejected `input`, so request text can reach logs.
- `APP_ENABLE_LANGSMITH` (`config/settings.py:48`) is never read; the behaviour
  change belongs to #8, but the setting's docs currently promise a switch that does
  nothing.
- On Agent Server, `configure_logging` is never called, so graph logs are not JSON
  and lack service metadata.

Acceptance criteria:
- [ ] Validation failures log only each error's `type` and `loc`; a test sends a
      message containing a marker string and asserts it is absent from all logs.
- [ ] Loading the graph module via `langgraph.json` configures JSON logging once
      (idempotent with the API's call); test covers it.
- [ ] `.env.example`/`OPERATIONS.md` describe `APP_ENABLE_LANGSMITH` accurately
      (marked "takes effect in #8" until then).

## 3. CI: run the eval-marked suites on every PR

**Labels:** `ci`, `evaluation` · **Depends on:** none

`ci.yml` passes `tests/evals` to pytest, but the default addopts deselect the
`eval` marker, so CI runs no eval tests (dataset shape checks and the fake-model
harness tests included).

Acceptance criteria:
- [ ] A CI step runs `pytest tests/evals -m "eval and not live"` (or equivalent) on
      every PR, on the existing OS matrix, with no provider key.
- [ ] Live tests are marked so they cannot run in this step; they skip, not fail,
      without a key.
- [ ] The step fails if zero tests were selected.
- [ ] `make eval` and `DEVELOPMENT.md` document the split.

## 4. OpenTelemetry foundation: SDK setup, settings, semconv module, log correlation

**Labels:** `observability`, `enhancement` · **Depends on:** 1

Acceptance criteria:
- [ ] `observability/telemetry.py` configures tracer and meter providers with the
      OTLP/HTTP exporter when `APP_OTEL_ENABLED=true`; otherwise the global no-op
      providers are used and no exporter or network call is created (test).
- [ ] New settings in `Settings` and `.env.example` (the `.env.example` sync test
      passes): `APP_OTEL_ENABLED`, `APP_OTEL_SERVICE_NAME`, endpoint/headers via the
      standard `OTEL_EXPORTER_OTLP_*` variables read through `Settings`,
      `APP_OTEL_TRACES_SAMPLE_RATIO` (head sampling, default 1.0).
- [ ] Resource attributes: `service.name`, `service.version`,
      `deployment.environment.name`.
- [ ] `observability/semconv.py` defines every span/metric/attribute name used,
      with the semconv version it is pinned to; no string literal attribute names
      elsewhere (lint-style test).
- [ ] FastAPI instrumentation excludes `/health/*`; HTTP spans use route templates.
- [ ] A structlog processor adds `trace_id`/`span_id` when a valid span is current;
      test asserts a log line inside a request carries the request's trace id.
- [ ] Incoming W3C `traceparent` is honoured; `X-Correlation-ID` remains the
      correlation id and is recorded on the server span.
- [ ] Exporter failure never fails a request (test with an unreachable endpoint).
- [ ] `make format lint typecheck test security` pass; `pip-audit` clean.

## 5. Agent tracing: `invoke_agent`, `chat`, `execute_tool` and stream spans

**Labels:** `observability`, `enhancement` · **Depends on:** 4

Acceptance criteria:
- [ ] `invoke_agent neuron` span per run on both paths (`AgentService` and the graph
      node under Agent Server), with `gen_ai.conversation.id`, `neuron.run_id`,
      `neuron.owner_key_prefix` (12 chars, never the full key), `neuron.turn`.
- [ ] `chat {model}` CLIENT span per model call from the existing agent middleware,
      with `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`,
      token usage by kind, retry count, and `error.type` = `AppError.code` on failure.
- [ ] `execute_tool {tool}` span per tool call with `gen_ai.tool.name`, outcome and
      `error.type`; authorization denials are visible as span status, not content.
- [ ] `neuron.stream` span covers the whole SSE stream: time to first visible token,
      events, termination reason (completed, cancelled, failed).
- [ ] Privacy test: run fake-model requests (including a tool call and a failure)
      with an in-memory span exporter; assert no span/event attribute contains the
      prompt, answer, tool arguments, tool result, bearer token or raw `sub`.
- [ ] Span tree test: one trace contains HTTP → invoke_agent → chat/execute_tool in
      the expected parent/child order.
- [ ] Agent Server run counts tokens into the span (closes the `usage=None` gap for
      telemetry; budgets on Agent Server remain out of scope).

## 6. Token and cost accounting by kind and model

**Labels:** `observability`, `enhancement` · **Depends on:** 1

Today `TokenUsageAccumulator` sums only a total and no cost is computed.

Acceptance criteria:
- [ ] Usage is recorded per model call as input, output, cache-read and reasoning
      tokens when the provider reports them; budgets still charge the total
      (existing budget tests unchanged).
- [ ] `config/model_pricing.json` (versioned, with `as_of`) maps model ids to USD per
      million tokens by kind for the models in `.env.example`; loaded and validated
      at startup.
- [ ] Each run logs `model_token_usage` with the split and `estimated_cost_usd`;
      unknown models log tokens and a single `model_pricing_missing` warning.
- [ ] Unit tests cover cost arithmetic, missing kinds, unknown models and invalid
      pricing files (startup fails closed).
- [ ] `OPERATIONS.md` explains that cost is an estimate and how to update pricing.

## 9. Eval harness v2: repeated trials, pass^k, intervals, trajectory and cost

**Labels:** `evaluation`, `enhancement` · **Depends on:** 1 (6 for cost fields)

Acceptance criteria:
- [ ] `neuron-eval --trials k` (default 1) runs each case k times; the report gives
      per case, category and suite: pass rate, pass^k, and a 95% Wilson interval.
- [ ] Trajectory matching per case: `unordered` (default) or `subset`; every case
      also asserts no tool outside the caller's permissions ran.
- [ ] Report schema is versioned (`report_version`) and adds latency p50/p95,
      tokens by kind and estimated cost per case and suite, model, git SHA and
      dataset versions; a JSON Schema file under `tests/fixtures` validates it.
- [ ] Run failures are classified: infrastructure (provider, quota, timeout,
      configuration) vs quality; infrastructure errors are reported separately and
      never counted as quality passes.
- [ ] `--suite`, `--category` and `--output <file>` options; stdout stays JSON.
- [ ] Fake-model tests cover k>1 aggregation, interval maths and classification.
- [ ] `EVALUATION.md` documents the metrics and how to read them.

## 10. Eval baselines, regression comparison and the live-eval workflow

**Labels:** `evaluation`, `ci` · **Depends on:** 3, 9

Acceptance criteria:
- [ ] `neuron-eval compare <baseline> <candidate>` exits non-zero when a gated suite
      (regression, security) drops below the baseline beyond its interval, and
      prints per-category deltas; tests cover pass, regression and noise cases.
- [ ] `evals/baselines/<model>.json` committed for the release baseline model, from
      a live run with `--trials 3` or more.
- [ ] A scheduled (nightly) and manually-triggered workflow runs the live suites
      when the provider secret is configured, skips cleanly when it is not, runs
      `compare` against the committed baseline, and uploads the report artifact.
- [ ] With `APP_ENABLE_LANGSMITH`, results are also uploaded as a LangSmith
      experiment (optional, off by default).
- [ ] Workflow uses least-privilege permissions and never prints secrets.
- [ ] `EVALUATION.md` documents how to refresh a baseline and who approves it.

## 11. Quality evals with calibrated LLM judges (reported, not gated)

**Labels:** `evaluation`, `enhancement` · **Depends on:** 9

Acceptance criteria:
- [ ] A quality dataset (v4-quality) of at least 30 rubric cases drawn from the
      existing categories and real failures, including "should not answer" cases.
- [ ] Judges are binary, one dimension each (e.g. answers the question, faithful to
      tool results, appropriate refusal), with a pinned judge model and versioned
      prompts under `prompts/`.
- [ ] Judge outputs are structured (verdict + short rationale) and an "unknown"
      verdict is allowed and reported separately.
- [ ] A calibration script computes TPR/TNR against a labelled set; the README for
      the suite states the current calibration and that the suite is report-only
      until TPR and TNR >= 0.9 on >= 100 labelled runs.
- [ ] The judge sees only the eval case and answer, never production data.
- [ ] Fake-judge tests cover parsing, unknown verdicts and aggregation.

## 12. User feedback endpoint tied to runs

**Labels:** `api`, `enhancement` · **Depends on:** 5 (scope confirmed in 1)

Acceptance criteria:
- [ ] `POST /v1/threads/{thread_id}/runs/{run_id}/feedback` with
      `{score: -1 | 1, reason?: <enum>}`; free text is rejected.
- [ ] Requires a new `feedback:write` scope and thread ownership, returning the same
      `404` for missing and foreign threads (BOLA matrix extended).
- [ ] Rate-limited like other `/v1` routes; idempotent per (owner, run).
- [ ] Recorded as a `user_feedback` log event, a span event and a metric by score
      and reason; forwarded to LangSmith feedback when enabled.
- [ ] OpenAPI, README and the security docs updated.

## 14. Security eval dataset v4: injection and policy invariants with pass^k

**Labels:** `evaluation`, `security` · **Depends on:** 9

Acceptance criteria:
- [ ] At least 12 new cases: direct prompt injection aimed at tool use and system
      prompt disclosure, injection carried across turns, injection via tool-shaped
      text in the user message, and scope escalation attempts.
- [ ] Assertions are on state and invariants only (tools that ran, permissions,
      thread isolation, no system prompt disclosure markers), never on a judge.
- [ ] The security suite gates on pass^k = 100% with k >= 3 in the live workflow.
- [ ] Optional: a documented Promptfoo red-team config for manual runs against a
      local instance (not a dependency, not in CI).

## 15. Readiness: probe JWKS reachability in `/health/ready`

**Labels:** `operations`, `bug` · **Depends on:** none

v0.4.0 known issue: an instance marked not ready after an IdP outage recovers only
when it serves a request.

Acceptance criteria:
- [ ] In jwt mode, `/health/ready` refreshes the JWKS when the last fetch failed,
      at most once per throttle window, and reports ready when it succeeds.
- [ ] A readiness call never makes a model call and never blocks longer than a
      bounded timeout.
- [ ] Tests cover outage, recovery and throttling; the CHANGELOG known issue is
      removed.
