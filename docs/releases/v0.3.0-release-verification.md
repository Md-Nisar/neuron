## Behavioural Verification (real servers)

**Restart survival (Postgres).** `test_thread_state_survives_service_restart`:
1. A thread is created by user A.
2. The service is shut down, and a new service instance is started against the same database.
3. A foreign user B gets `ThreadNotFoundError`.
4. The owner A continues the thread; 4 messages are persisted.

**SSE through a reverse proxy.**
- Setup: nginx 1.27 with the exact `location` block from `OPERATIONS.md`, in front of uvicorn, with a model that emits one token every 0.5 s.
- Event arrival times (s), as seen by the client:

  ```
  [(0.01, 'run_started'), (0.53, 'token'), (1.03, 'token'), (1.53, 'token'),
   (2.03, 'token'), (2.53, 'token'), (3.03, 'token'), (3.04, 'final'), (3.04, 'done')]
  ```
- Result: tokens arrive at the rate they're generated, so there is no proxy buffering.

**Failure paths (uvicorn, slow streaming model):**

| Scenario | Observed |
| --- | --- |
| Client disconnects after ~1.6 s | 3 tokens produced, 3 received. The model call received `CancelledError`; `stream_cancelled termination=client_disconnect` |
| Run longer than `APP_RUN_TIMEOUT_SECONDS=3` | `error {"code": "run_timeout", "retryable": true}`, then `done` |
| Second request on a thread with a run in flight | `409 {"detail":"thread_busy"}`; `200` once the first client left |
| SIGTERM mid-stream | `error {"code": "service_shutting_down", "retryable": true}`, then `done`; model call cancelled |
| Postgres stopped, then restarted (#21) | readiness `503`, then `200`; invoke `503`, then `200` |

**Agent Server (`langgraph dev`, langgraph-api 0.13.2):**
- The `main` graph is registered.
- Two `runs/wait` calls on one Agent Server thread give the history `human:first turn, ai:…, human:second turn, ai:…`, so Agent Server's own persistence works with the graph.
- A `runs/stream` call with `messages-tuple` and `stream_subgraphs` emitted 21 message events.

**README examples** (#29), run verbatim against the compose Postgres service:

## Findings

### Fixed during this gate run
- **Agent Server and Studio runs always failed (present since 0.2.0).**
  - Cause: inputs carry only `messages`. `agent_invocation_config` called `uuid.UUID(None)` for the missing `run_id`, so every run through the `langgraph.json` deployment path raised `AgentExecutionError`.
  - Fix: `run_id` is now passed only when supplied.
  - Regression tests: `test_agent_server_input_without_correlation_ids_runs`, `test_agent_invocation_config_omits_missing_run_id`.
- **The live OpenAI smoke test could never pass (present since 0.2.0).**
  - Cause: `tests/integration/test_live_openai_smoke.py` called `graph.invoke` synchronously, but the agent node is async. LangGraph raised `TypeError: No synchronous function provided to "agent"` before any provider call.
  - How it was found: the first run with a real key, on Windows.
  - Fix: the test now uses `await graph.ainvoke`.
- **`.env.example` set `APP_VERSION=0.1.0`,** so a copied `.env` misreported the service version in every log line. It now matches the release.

### Fixed earlier in v0.3.0 (found while implementing)
- **Nested agent state was checkpointed** (`agent:<id>` namespace, tool calls and results) (#22).
- **Model calls kept running after a client disconnect** under sse-starlette's anyio cancel scope (#25).
- **Stream leases leaked when sending failed,** and the run budget could be bypassed by a client that stopped reading. Both came from security review (#25).
- **The Postgres saver was built outside the event loop,** crashing startup, and the pool didn't recover after a database restart (#21).

### Reported separately (not fixed in this release)
- **Empty `OPENAI_API_KEY` disables the fake-model fallback.** `.env.example` ships `OPENAI_API_KEY=` empty, which is treated as a configured key, so the documented fallback doesn't apply and a fresh local setup crashes when it builds the model client. Queued as a separate task.
- **Container image build couldn't be verified here.**
  - Blockers: Docker Hub rate-limited this environment (429), and `ghcr.io` blob downloads are blocked (403).
  - Possible Dockerfile problem: the existing builder tag `ghcr.io/astral-sh/uv:0.11.29-python3.13-bookworm-slim` also returned "not found".
  - Action: run `docker compose up --build` once with normal network access.

## Known Limitations of This Gate Run
- **No live provider calls:**
  - the live OpenAI invoke and streaming smoke tests;
  - live eval v1 (16 cases) and v2 (13 cases, 46 calls);
  - real time-to-first-token and latency measurements.

  These are the remaining unchecked exit criteria.
- **The `thread_busy` guard and stream cap are per process.** Concurrent same-thread requests on different replicas aren't rejected (documented in ADR 0005 and `OPERATIONS.md`).
- **`user_id` is unauthenticated until v0.4.0.** Thread ownership relies on server-minted UUIDv4s for real protection.

## Remaining Risks
- **Structured-output token streaming is untested against the real OpenAI provider.** It is covered with fake models for both the provider-JSON and tool-call strategies.
- **`langgraph-api` 0.13.2** (dev dependency for `langgraph dev`) reports end-of-life; upgrade it separately.
- **Postgres checkpoint growth:** checkpoint history grows per step until a thread is pruned or deleted. Schedule `make prune-threads`.
