# v0.8.0 "User Application": Issue Drafts

Drafts for the v0.8.0 milestone, derived from ADR 0010 (Accepted). Filed on GitHub on
2026-10-28 as #275 to #293 (draft N is issue #(274+N)), with the tracker #294; the issues
are the source of truth from here on. Each draft is sized for one PR
under about 400 changed lines. Everything is verified locally (fake model, local Keycloak,
NVIDIA development model if a valid key exists); production and staging are not exercised
(owner decision, 2026-10-27).

Labels: the existing set plus a `v0.8.0` label and `frontend`.

The ADR's four open questions are decided inside the issues that need them (#279, #277, #282).

## Drafts

### 1. ADR 0010: user application
`architecture`, `documentation`, `priority:p0` · Depends on: none
- [ ] ADR 0010 is reviewed and set to Accepted; its open questions are answered.
- [ ] `ARCHITECTURE.md`, `docs/ROADMAP.md` and `CLAUDE.md` link it and name the `web/` module boundary.

### 2. Run id on the stream
`api`, `priority:p0` · Depends on: 1
- [ ] `run_started` and `final` carry `run_id`; `STREAM_PROTOCOL_VERSION` stays 1; the
      contract test and README are updated.
- [ ] The id is a server-generated UUID, never client-supplied, and is the one in graph state.

### 3. Conversation titles
`api`, `state`, `privacy`, `priority:p0` · Depends on: 1
- [ ] A bounded title (80 characters) is set from the first user message, owner-keyed,
      stored per ADR 0010 decision 6 with a migration following ADR 0008.
- [ ] `PATCH /v1/threads/{id}` renames (scope `threads:write`); foreign and missing threads
      are the same 404; the BOLA matrix covers the route.
- [ ] `GET /v1/me/threads` returns the title; export, thread delete and erase cover it.
- [ ] Titles never appear in logs, spans or metrics (leak test).

### 4. History replay includes tool calls and approvals
`api`, `priority:p1` · Depends on: 1
- [ ] `GET /v1/threads/{id}/messages` includes tool-call records (tool name, bounded
      server-rendered argument summary, status) and the approval outcome.
- [ ] Tool output text is not returned; summaries are length-bounded; tests cover an
      approved, a rejected and a pending approval.

### 5. Keycloak development stack
`security`, `dev-experience`, `priority:p0` · Depends on: 1
- [ ] `docker-compose` gains a pinned Keycloak (`start-dev`) importing realm `neuron`: public
      PKCE client, audience mapper (`aud=neuron-api`), roles mapped to the `roles` claim,
      two dev users with different roles; no real credentials (a test greps the export).
- [ ] `make dev-keycloak` prints the `APP_AUTH_*` settings; the API accepts a Keycloak token
      and refuses a wrong-audience, expired and `alg=none` token (integration test against
      the container, marked and excluded from `make test`).
- [ ] Production settings validation is unchanged; a unit test shows HTTP issuers are still
      refused outside development.

### 6. Web scaffold
`frontend`, `ci`, `priority:p0` · Depends on: 1
- [ ] `web/` with Vite, React, strict TypeScript, Tailwind, shadcn/ui setup, ESLint,
      Prettier, Vitest; Node and package manager pinned; lockfile committed.
- [ ] A CI job runs install from the lockfile, lint, typecheck, test and `npm audit`;
      new packages pass the 90-day rule; the root Makefile gains `web-*` targets.
- [ ] `.gitignore`, `.dockerignore` and CodeQL cover `web/`; the API image does not include it.

### 7. SSE stream client
`frontend`, `priority:p0` · Depends on: 6
- [ ] A typed client parses all seven events from a `fetch` stream, supports abort,
      surfaces `error` then `done`, and handles 401, 409 `thread_busy` and 429 `Retry-After`
      before the first byte.
- [ ] Tests against a fake SSE server: split chunks, partial UTF-8, mid-stream error, abort,
      heartbeat comments, unknown event ignored.
- [ ] Token deltas are a preview; `final` replaces them.

### 8. Sign-in
`frontend`, `security`, `priority:p0` · Depends on: 5, 6
- [ ] Authorization Code + PKCE (S256) against Keycloak; state and nonce checked; the
      redirect target is a fixed allow-list (no open redirect).
- [ ] The access token is held in memory only; a test fails if it reaches `localStorage`,
      `sessionStorage`, cookies, the URL after the callback, or console output.
- [ ] Expiry shows a re-login prompt; silent renew is attempted per ADR 0010 open question 2.
- [ ] Sign-out ends the Keycloak session and clears memory.

### 9. Chat screen
`frontend`, `priority:p0` · Depends on: 7, 8
- [ ] Send, stream, stop, retry, new conversation; input limits match the API's.
- [ ] Sanitised markdown (no raw HTML, no model-loaded images, safe links, code as text).
- [ ] Error states for 401, 403, 409, 429, 5xx and a broken stream; partial answer kept.

### 10. Conversation list
`frontend`, `priority:p0` · Depends on: 3, 9
- [ ] Sidebar from `GET /v1/me/threads` with titles and paging; rename, delete (with confirm).
- [ ] Empty, loading and error states; the list refreshes after a run.

### 11. Feedback API (#104)
`api`, `security`, `priority:p1` · Depends on: 2
- [ ] `POST /v1/threads/{id}/runs/{run_id}/feedback` per ADR 0010 decision 6 and issue #104:
      scope `feedback:write`, fixed enum, no free text, idempotent per (owner, run), 404
      for missing and foreign, rate-limited, BOLA matrix extended.
- [ ] Log event, span event and metric by score and reason, names added to `semconv.py`
      and the Collector allow-list; leak scan passes. LangSmith forwarding only when enabled.
- [ ] OpenAPI, README and `SECURITY.md` updated.

### 12. Resume a conversation
`frontend`, `priority:p0` · Depends on: 4, 9, 10
- [ ] Opening a conversation loads history (with tool and approval records) and continues it.
- [ ] A conversation that ended `approval_required` shows the pending card or its outcome.

### 13. Approval card
`frontend`, `security`, `priority:p0` · Depends on: 9
- [ ] Rendered only from the server's `approval_required` payload; approve and reject call
      the approval streaming endpoint and show the continuation.
- [ ] Model text cannot create, style or resolve a card (tests with look-alike text and
      markdown); double-click and a second tab give one decision and a clear message.
- [ ] A rejected or expired approval shows a neutral outcome; the decision is never
      inferred from the model's wording.

### 14. Memories and data rights
`frontend`, `privacy`, `priority:p1` · Depends on: 8
- [ ] List and delete memories; export downloads the JSON from `/v1/me/export`; erase
      requires a typed confirmation and signs the user out afterwards.
- [ ] The export file is never cached or kept in memory after the download.

### 15. Feedback in the UI
`frontend`, `priority:p1` · Depends on: 9, 11
- [ ] Thumbs up and down with the fixed reasons on each completed answer; one rating per
      run; failures are shown without blocking the chat.

### 16. UI security tests
`frontend`, `security`, `testing`, `priority:p0` · Depends on: 9, 13
- [ ] XSS payloads in `token`, `final`, titles and tool summaries render as text; markdown
      image beacons make no request; look-alike approval text does nothing; the callback
      rejects an unlisted redirect; the CSP blocks inline script (Playwright).
- [ ] A test fails if the app loads any third-party origin or sends analytics.

### 17. Accessibility and responsive layout
`frontend`, `priority:p1` · Depends on: 9, 10, 13, 14
- [ ] axe finds no serious or critical issue on chat, list, approval, memories; keyboard-only
      use works; focus is managed on stream end and on the approval card.
- [ ] Layout works at 360 px; dark mode follows the system.
- [ ] A manual screen-reader pass is recorded in the release record.

### 18. Docs, operations and CSP
