# v1.2.0 reranking evaluation: NVIDIA reranker against RRF

RAG-09.01, acceptance criterion 2: compare reranking with reciprocal rank fusion (RRF) on the
eval corpus, record the numbers, and let the default follow them. Run on 2026-11-12.

## Method

- **Corpus and vectors.** As the retrieval gate (`tests/integration/test_postgres_knowledge_retrieval.py`):
  the RAG-00.03 dataset through Neuron's parsers and chunker (`tests/fixtures/knowledge/eval/parsed.json.gz`),
  1,999 chunks at 400 tokens, with their committed `nvidia/nemotron-3.5-embed-1b` vectors. 64
  answerable cases, each searched as its own user, `k` = 10. No embedding provider is called.
- **Orders compared.** RRF (the v1.1.0 hybrid search) and the same search reranked: the fused top
  40 sent to `nvidia/llama-nemotron-rerank-vl-1b-v2` on NVIDIA's API catalog as heading path, a
  newline, then the passage text, and the best 10 of its order kept. A case is a hit when a
  returned passage is on an expected page or section.
- **Command.**

  ```bash
  NVIDIA_API_KEY=... APP_TEST_POSTGRES_DSN=postgresql://postgres:pw@127.0.0.1:55432/postgres \
  APP_KNOWLEDGE_EVAL_REPORT=rerank.json \
  uv run python -m pytest tests/integration/test_live_knowledge_rerank.py -m integration \
    -o faulthandler_timeout=900
  ```

## Results

| Order | recall@5 | MRR | recall@1 |
| --- | --- | --- | --- |
| RRF | 0.984 | 0.833 | 0.734 |
| Reranked | 0.984 | **0.924** | **0.875** |

A whole search with reranking took 0.631 s at p50 and 0.742 s at p95 (64 searches, one host,
Postgres in Docker, NVIDIA's hosted endpoint). The reranker call alone measured 0.51 to 0.54 s at
p50 in the exploratory run below.

An exploratory run the same day, calling the API directly, sent the passage text alone: MRR
0.883 and recall@1 0.813, but recall@5 fell to 0.969 (one case). Sending the heading path too
recovered it, so the adapter sends both.

One earlier run of the test ended inconclusive: one reranker call answered `502`, the search fell
back to RRF with `reranked: false` as designed, and the test refuses to score a run with a
fallback. The next run had none.

## Decision

Reranking keeps recall@5 and raises MRR by 0.09 and recall@1 by 0.14, for about half a second per
search. The default follows the numbers: `APP_KNOWLEDGE_RERANKER` unset means `nvidia` when the
embedding provider is `nvidia` and `NVIDIA_API_KEY` is set (the query and passages already go to
NVIDIA for embedding), and `none` otherwise. A self-hosted deployment gets no hosted reranker
unless it sets one, and `self_hosted_only` refuses it in staging and production.

## Limits

- One corpus of 31 documents and one run; the reranker is deterministic, the network is not.
- recall@5 is near its ceiling on this corpus, so the gain shows in MRR and recall@1: the first
  passage is more often the right one, which is what the agent reads first.
- The latency is NVIDIA's hosted endpoint from one location; a self-hosted reranker (`tei`, later
  in RAG-09.01) would differ.
