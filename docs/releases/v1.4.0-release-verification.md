# v1.4.0 release verification

Release record for v1.4.0 "Questions about tables": the v1.4.0 scope of RAG-E11 in
`docs/product/NEURON_RAG_PRODUCT_BACKLOG.md`, one story, RAG-11.01 `query_table` over uploaded
tables (epic #593, story #594). The assistant can answer a question that needs every row of an
uploaded spreadsheet or CSV file, such as a total, a count, an average or the largest group. The
worker stores each table of an XLSX or CSV upload with typed columns. The agent finds a table
with `find_tables` and runs one read-only SQL query on it with `query_table`. The answer cites
the table's document and sheet. The other nine stories of RAG-E11 and RAG-E12 are deferred for
want of a product need (tracker, "Epic detail"). Knowledge stays off by default
(`APP_KNOWLEDGE_ENABLED`). The `/v1` API and stream protocol version 1 stay compatible:
- CSV uploads, the two tool scopes and the citation's `table` field are additions;
- `chunk_id` is `null` on a table citation;
- `citation_schema_version` stays 1.

Migration 31 runs only with knowledge on.

**No production environment exists**, as for v1.0.0 to v1.3.0. All evidence is local: a
pgvector container, CI, and the NVIDIA free tier for the live checks.

**Signed off:** by the owner when this record's pull request is approved. **Released:** from
the merge of this record's pull request. As for v1.3.0, the owner makes the tag `v1.4.0` and the
GitHub Release by hand from the `1.4.0` CHANGELOG section.

## Notes on the local evidence

- The upgrade check (criterion 7) ran `setup` from both commits against one database in the
  pinned `pgvector/pgvector:pg16` image. The seeded rows were written with SQL, not through the
  API. Images for the reference stack were not built: Docker Hub rate-limited this session's
  pulls (`429`). The API smoke test after the upgrade is not part of this record.
- The live evals ran one trial each on the NVIDIA free tier. The table eval's model check is in
  `EVALUATION.md`, "Development models".
- To see whether criterion 9's miss is the model's, the answer eval also ran on 2026-11-16 on
  Nemotron Super VL and Nemotron Lightning (the reranker was unavailable for these and for the release run, see "Known issues"). No model met every
  gate: Super VL abstained 12 of 12 but `cited_correctly` was 0.859; Lightning was 0.948 and
  abstained on every case it finished, but 7 cases ended in a structured-output error. Retrieval
  was the same for all (recall@5 0.984, MRR 0.833). `answerable-044` and `-048` were missed by
  all three models.

## Known issues

- No production environment, staging run or production-model run. The `production` job of
  `deploy.yml` cannot succeed, so the GitHub Release is published by hand from the `1.4.0`
  CHANGELOG section (`python3 scripts/changelog_section.py 1.4.0`).
- A model can answer a table question from search without calling `find_tables` (`table-002`,
  once in 12 close-out aggregates). Once it calls `find_tables`, it is made to query.
- Only tables of XLSX and CSV uploads are stored, and documents ingested before 1.4.0 have none
  until deleted and uploaded again. A table over the caps stays text only. SQLite's 256 MB heap
  limit is shared by the process.
- ADR 0014's amendment "tables" names a cap of 100 columns a table; the code does not enforce
  one. The cell cap (`APP_KNOWLEDGE_TABLE_MAX_CELLS`) bounds a table's size.
- The live answer eval missed one abstention (criterion 9), as in v1.3.0; the owner accepted it.
- NVIDIA retired the default reranker (`nvidia/llama-nemotron-rerank-vl-1b-v2`) on 2026-11-16
  at 09:00 UTC; it answers `410 Gone`. Search keeps the hybrid order, the designed fallback, and
  logs `knowledge_rerank_skipped`. Not a 1.4.0 change; it affects 1.2.0 onwards. NVIDIA serves
  `nvidia/nemotron-3.5-rerank-8b` with the same request (checked with the development key on
  2026-11-16; 0.4 to 4.7 seconds for 20 to 31 passages), but 1.4.0 cannot call it by setting
  `APP_KNOWLEDGE_RERANKER_MODEL`: the adapter writes dots as underscores in the URL, and
  `nemotron-3_5-rerank-8b` answers `404`. Until #620, set `APP_KNOWLEDGE_RERANKER=none`.
- Unchanged from v1.3.0: JavaScript-built pages, one fetch per page, no per-host fetch limit,
  the one-trial live answer eval, local-only load figures, the hosted-only reranker, German word
  search, no worker settings profile, and the erase-flow browser test's race.
