# v1.1.0 release verification

Release record for v1.1.0 "Knowledge Engine" (RAG-08.05, #520): RAG-E00 to RAG-E08 of
`docs/product/NEURON_RAG_PRODUCT_BACKLOG.md`, 33 stories. Users upload documents to their own
knowledge bases; a separate worker ingests them into Postgres with pgvector; answers cite the
passages they used, and the server checks every citation. Knowledge is off by default
(`APP_KNOWLEDGE_ENABLED`). The `/v1` API and stream protocol version 1 stay compatible: the
knowledge routes and citation fields are additions. Migrations 17 to 27 run only with knowledge on.

**No production environment exists**, as for v1.0.0. All evidence is local: the reference stack
(`docker-compose.reference.yml`), CI, and the NVIDIA free tier for the live answer eval.

## Load figures

`scripts/knowledge_load.py` on the reference stack at `b52272f` (2026-11-10): a 4-CPU, 15 GB
container host; two API replicas, one worker, the fake embedding provider and the Markdown parser
only. They measure the queue, chunking, storage and retrieval, not an embedding provider or
docling. Not comparable with hosted capacity.

| Ingestion | Result |
| --- | --- |
| Documents | 80 Markdown files of 16 KB, from 8 users, at most 5 in flight per user; all `ready` |
| Throughput | 251.6 documents a minute (80 in 19.1 s) |
| Upload to `ready` (server time) | p50 4.8 s, p95 7.3 s, max 7.7 s |
| Refused uploads | 10 `429 ingestion_concurrency_exceeded` (the per-user cap of 5), retried |

| Search (`POST /v1/knowledge/search`, k = 5, one base) | Result |

## Known issues

- No production environment, staging run or production-model run. The `production` job of
  `deploy.yml` cannot succeed, so the GitHub Release is published by hand from the `1.1.0`
  CHANGELOG section (`python3 scripts/changelog_section.py 1.1.0`).
- The live answer eval was not re-run on the release commit (criterion 12). With one trial per
  case, runs 2 to 6 ranged from 0.891 to 0.952, so a re-run can land near the 0.9 gate.
- Load figures describe one local host with fake embeddings; the ADR 0012 comparison with v0.9.0
  was not run; the load gate is RAG-09.06 (v1.2.0).
- No story yet for a worker settings profile (RAG-E02 follow-up) or for checking the worker role's
  column grants in production.
- A slow embedding call can outlast the 20-second tool timeout (`APP_TOOL_TIMEOUT_SECONDS`) and
  fail the run instead of reporting knowledge unavailable (`v1.1.0-retrieval-eval.md`).
- The restore drill seeded no memories with knowledge on, so memories were not checked after a
  restore (`v1.1.0-restore-drill.md`).
- #480 stays open; its items were not all re-checked for this release.
- Deferred to Phase 2 (v1.2.0, RAG-E09): reranking, shared knowledge bases, a retrieval
  regression gate and the load gate.
