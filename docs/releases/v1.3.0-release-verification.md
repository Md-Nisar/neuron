# v1.3.0 release verification

Release record for v1.3.0 "Web pages": the v1.3.0 scope of RAG-E10 in
`docs/product/NEURON_RAG_PRODUCT_BACKLOG.md`, 3 stories (epic #577): outbound URL safety
(RAG-10.01, #578), the OpenAI-compatible chat model provider (RAG-10.05, #582) and web page
ingestion (RAG-10.02, #579). A user can add a public `https` web page to a knowledge base by its
address; the worker fetches it once through a public-only client, stores that version with its
hash and fetch time, and every citation of it carries the page's URL and fetch time. A deployment
can run its chat model on a self-hosted OpenAI-compatible server. GitHub sync (RAG-10.03, #580)
and MCP connectors (RAG-10.04, #581) were deferred by the owner and closed as not planned.
Knowledge stays off by default (`APP_KNOWLEDGE_ENABLED`). The `/v1` API and stream protocol
version 1 stay compatible: the web-pages route and the `source_url` and `fetched_at` fields are
additions, and `citation_schema_version` stays 1. Migration 30 runs only with knowledge on.

**No production environment exists**, as for v1.0.0 to v1.2.0. All evidence is local: the
reference stack (`docker-compose.reference.yml`), CI, and the NVIDIA free tier for the live checks.

**Signed off** by the owner on 2026-11-13, before this record was written. **Released** from the
merge of this record's pull request; the tag `v1.3.0` and the GitHub Release are made by hand from
the `1.3.0` CHANGELOG section, as for v1.2.0 (the session's GitHub credentials cannot push a tag).

## Notes on the local evidence

- The images were built with this sandbox's TLS proxy CA trusted in the builder stage only; the
  runtime image is the repository's `Dockerfile`.
- The sandbox intercepts outbound TLS, so the worker container's first fetches failed certificate
  verification and were retried as `fetch_failed`, as designed. For the check, the worker ran with
  the sandbox CA mounted as its system trust store. The fetch client verifies against the system
  trust store, not `certifi`.
- The session's disk allowance filled during the first successful fetch, so that ingest failed
  after the page was stored; the document was deleted and the page added again with space free.

## Known issues

- No production environment, staging run or production-model run. The `production` job of
  `deploy.yml` cannot succeed, so the GitHub Release is published by hand from the `1.3.0`
  CHANGELOG section (`python3 scripts/changelog_section.py 1.3.0`).
- Pages are fetched as plain HTML: a page that builds its text with JavaScript yields `no_text`.
  A page is fetched once, with no re-fetch, and each URL variant is its own page.
- No per-host rate limit on fetches; a user's quota and the base's document limit bound them.
- A worker without direct internet access gets `fetch_failed` for every page.
- The OpenAI-compatible chat provider was tested against a local fake server, not a running vLLM
  or SGLang.
- The live answer eval failed both release runs (criterion 9): correct citations stayed above the
  0.9 gate, but each run answered one unanswerable near-miss question instead of declining, and
  NVIDIA's free tier timed out or rate-limited some cases. The owner accepted this for v1.3.0.
- Unchanged from v1.2.0: the one-trial live answer eval, local-only load figures, the hosted-only
  reranker, German word search, no worker settings profile, and the erase-flow browser test's race.
