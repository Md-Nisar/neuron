# v1.0.0 release verification

Release record for v1.0.0 "Production AI Application". v1.0.0 is the v0.9.0 candidate
(`v0.9.0-release-verification.md`) plus the 26 commits merged to `main` during the release freeze:
fixes, tests, dependency updates and the Keycloak login theme. The `/v1` API, stream protocol
version 1, the existing `APP_*` setting names and the migrations are unchanged; no migration was
added. Two `OTEL_*` header settings were added and are held to the existing HTTPS rule (`CHANGELOG.md`,
upgrade note).

**No production environment exists.** No hosted deployment (Render), staging run, OpenAI
production-model run, Anthropic live run or external penetration test has run for this or any
earlier release.

## Owner decisions (2026-11-02)

- **Released directly, without `v1.0.0-rc.N` tags.** ADR 0012 decision 12 planned release
  candidates before v1.0.0. The owner skipped them because there is no environment in which a
  candidate could be checked.
- **Open items are recorded as known issues, not blockers:** #374, #376 and the load re-run below.

## Quality gates

Run on the release branch (based on `main` at `2c46257`) in a Linux container with Python 3.13 and
no model credentials (the fake model):

| Gate | Result |
| --- | --- |
| `make format` | 205 files left unchanged |
| `make lint` | all checks passed |
| `make typecheck` | no issues in 96 source files |
| `make test` | 1964 passed, 2 skipped, 3 deselected |
| `make security` | bandit: no issues; dependency audit: no known vulnerabilities |

The `web-*`, `keycloak-theme`, `web-e2e`, CodeQL and AI-verification gates run in CI on the pull
request; they were not run locally.

## Known issues

- No production environment, staging run or production-model run (above). The `production` job of
  `deploy.yml` cannot succeed, so the `release` job, which waits for it, will not publish the
  GitHub Release for `v1.0.0`; it is published by hand from the `1.0.0` CHANGELOG section
  (`python3 scripts/changelog_section.py 1.0.0`).
- The load comparison against v0.9.0 was not run (criterion 5).
- #374: no automated local runner for the Postgres integration tests.
- #376: mypy covers `tests/conftest.py`, `tests/graph` and the resilience, e2e and eval tests;
  `tests/security`, `tests/integration` and `tests/unit` are not type-checked yet.
- The v0.9.0 model and capacity caveats still hold: load figures describe one local host, and
  `nemotron-3-ultra-550b-a55b` returns forced tool calls as text (#341).
- Still deferred until after v1.0.0 (`docs/ROADMAP.md`): hosted deployment and its restore and
  rollback, #285 (ratings to LangSmith) and an external penetration test.
