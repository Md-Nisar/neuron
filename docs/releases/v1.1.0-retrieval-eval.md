# v1.1.0 retrieval evaluation: dense, full text and hybrid

RAG-04.01, acceptance criterion 5: on the eval corpus, compare dense, full-text and hybrid search
and keep hybrid as the default only if its recall@5 is at least dense's. Run on 2026-11-04.

## Method

- **Corpus.** The RAG-00.03 dataset (`tests/fixtures/knowledge_cases.json`): 30 documents (the
  scanned log has no text layer and is left out), 21 of them public and downloaded from their
  URLs, each matching the dataset's SHA-256. 61 answerable cases (those citing the scanned log are
  left out), each searched as its own user.
- **Chunks and vectors.** The Phase 0 spike's chunks (RAG-00.02, question 2): pages, or sections
  for unpaginated documents, cut to 1,200 characters with 200 of overlap, 2,032 in all. The
  vectors are the spike's cached `nvidia/nemotron-3.5-embed-1b` embeddings at 1,024 dimensions
  (passages as `passage`, questions as `query`), so no provider was called. Neuron's own chunker
  (RAG-02.04) is not used here, because re-embedding needs an API key the session did not have.
- **Search.** `knowledge/retrieval.py` on Postgres 16 with pgvector, as the app role under RLS,
  with the default settings: 80 candidates per path, RRF k = 60, `simple` text-search config, no
  similarity floor. 2,032 chunks is under the 10,000 threshold, so the dense path is the exact
  scan. A case is a hit when a returned passage is on an expected page or section.
- **Command.**

  ```bash
  APP_KNOWLEDGE_EVAL_DIR=/path/to/corpus-and-vectors \
  APP_TEST_POSTGRES_DSN=postgresql://postgres:pw@127.0.0.1:55432/postgres \
  uv run python -m pytest tests/integration/test_postgres_knowledge_eval.py -m eval -o addopts=""
  ```

  The directory holds the public documents and the spike's `passages.npy` and `queries.npy`. The
  test writes `retrieval_eval.json` there and fails if the default mode disagrees with the rule.

## Results

| Mode | recall@1 | recall@5 | recall@10 | MRR@10 |
| --- | ---: | ---: | ---: | ---: |
| Dense | 0.721 | 0.918 | 1.000 | 0.799 |
| Full text | 0.016 | 0.033 | 0.033 | 0.022 |
| **Hybrid** | **0.754** | **0.918** | **1.000** | **0.819** |

Dense through Postgres matches the spike's in-memory recall@5 (0.918), which checks that the
chunks and vectors line up.

## Decision

**Hybrid stays the default** (`APP_KNOWLEDGE_SEARCH_MODE=hybrid`): its recall@5 equals dense's,
and it ranks the right passage first more often (recall@1 0.754 against 0.721).

Full text alone finds almost nothing for these questions: `websearch_to_tsquery` requires every
word of a natural-language question, which a passage rarely contains. Its value is exact terms,
such as identifiers and error codes, that embeddings miss (AC3). An `OR` query, or an English
config for English bases, are tuning candidates for the RAG-08.01 eval suite, not changes here.
