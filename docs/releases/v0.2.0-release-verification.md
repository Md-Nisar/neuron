## Findings

### Fixed during this gate run

**Every `/v1/agent/invoke` call failed with `500` when no `OPENAI_API_KEY` was configured** — i.e., the exact "no credentials" path that `README.md`/`ARCHITECTURE.md` document as supported (fake model keeps the app functional). Root cause: `langchain`'s `create_agent` unconditionally calls `model.bind_tools(...)` to wire the approved tool set; `FakeListChatModel` inherits `BaseChatModel.bind_tools`, which raises `NotImplementedError` by default. No existing test caught this because `tests/graph/test_main_graph.py` exercises `call_agent` against hand-written `FakeAgent`/`FailingAgent` doubles, never the real `create_agent` harness, and the live-model tests that do use the real harness are skip-gated on `OPENAI_API_KEY` — so the fake-model path through the production agent wiring had never actually been run end-to-end before this gate.

Fixed in `src/neuron_agent/models/factory.py` with a thin `FakeListChatModel` subclass whose `bind_tools` is a no-op (commit `14d7dcd`), plus a regression test building the real `create_main_agent(settings, tools=[utc_now, calculator])` harness against the fake model. Verified via the manual API smoke test above (first run `500`, second run after the fix `200`) and the full deterministic suite (125 passed).

### Resolved after user confirmation

**Version metadata read `0.1.0`** in `pyproject.toml`, `src/neuron_agent/__init__.py::__version__`, and `Settings.version` at the time of the checks above, blocking the "v0.2.0 tag/release is ready" exit criterion. Bumped to `0.2.0` in all three places plus `CHANGELOG.md` and `docs/ROADMAP.md` after explicit user confirmation; package rebuilt and the full gate re-run clean (see below).

## Known Limitations of This Gate Run

- **No live OpenAI smoke test was executed.** This sandbox has no `OPENAI_API_KEY` and no `.env` file. `tests/integration/test_live_openai_smoke.py` and the credentialed case in `tests/evals/test_agent_quality.py` both skipped cleanly (correct, documented behavior — see `README.md`/`EVALUATION.md`), but neither actually validated a real OpenAI round trip, real provider latency, or real retry/timeout behavior under network conditions. This must be re-run with credentials before tagging a release.
- Latency numbers above are fake-model-only and do not bound real provider latency.
- The rate-limit, failure-path, and bind_tools checks above were run against a single local process; they do not exercise multi-instance/multi-replica behavior (the in-process rate limiter's documented per-instance limitation, ADR 0004, was not re-verified under multiple processes).

## Remaining Risks

1. **The fake-model path had a real, user-facing defect that no test caught for the lifetime of issues #1–#10.** The regression test added here covers the specific `bind_tools` crash, but it's worth asking whether `tests/graph/test_main_graph.py`'s reliance on hand-written agent doubles (rather than the real `create_agent` harness) is leaving other gaps between the test doubles and production wiring — this gate only found the one bug it happened to exercise manually.
2. **Live provider behavior (retries, timeouts, real latency) is unverified in this run** (see Known Limitations) and should be re-checked with credentials before release.
3. **In-process rate limiting does not coordinate across replicas** — a pre-existing, documented limitation (ADR 0004), not new, but worth re-confirming it matches the actual production deployment topology before relying on the documented defaults at scale.
