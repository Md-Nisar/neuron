# v0.7.0 "Extensible Agent Platform": Issue Drafts

Drafts for the v0.7.0 milestone, derived from ADR 0009 (Proposed). Filed on GitHub on
2026-10-27 as #231 to #252, with the tracker #253; the issues are the source of truth
from here on. Draft numbers stay stable across review
rounds (a split draft gains a letter). Each draft is sized for one PR under about 400
changed lines. Everything is verified locally on the NVIDIA development model, with
fakes where a provider has no key; production and staging are not exercised (owner
decision, 2026-10-27), but production settings validation is extended and unit tested.

### 7. Tool registry
`architecture`, `security`, `priority:p0` · Depends on: 2
- [ ] `tools/registry.py`: one `ToolSpec` per tool (name, tool, scope, risk, source);
      allow-list, scope checks, approval config and span names derive from it.
- [ ] A tool with no spec is not callable; a `mutating` tool without approval fails a test;
      `HIGH_RISK_TOOL_NAMES` stays as an independent test.
- [ ] `add-tool` skill and `DEVELOPMENT.md` updated; no behaviour change for `utc_now` and `calculator`.

### 8. MCP server configuration and pinning
`security`, `priority:p0` · Depends on: 7
- [ ] `APP_MCP_SERVERS` (path to JSON): name, URL, per-tool pin (SHA-256 of name,
      description, input schema) and risk class (default `mutating`); unknown keys and
      stdio/SSE/WebSocket entries are refused at start-up.
- [ ] URL rules: `validate_safe_url`, `https`, loopback `http` only in development/test.
- [ ] A pure function checks a fetched tool list against the pins; unit tests for a
      changed description, a changed schema, an unlisted tool and a removed tool.

### 9. MCP client and reference server
`security`, `architecture`, `priority:p0` · Depends on: 8
- [ ] `langchain.mcp` adapter loads pinned tools once at start-up into the registry with
      the `mcp_<server>_` prefix and scope `tools:mcp.<server>.<tool>`; `list_changed`
      ignored; sampling, roots and elicitation off.
- [ ] Bearer secret per server, never the user's token; text results only, capped by
      `APP_MCP_MAX_OUTPUT_BYTES`; the existing timeout and failure isolation apply.
- [ ] In-repo loopback server with `convert_units`; the agent calls it in a graph test.
- [ ] New dependencies justified; `make security` and the dependency audit pass.

### 10. MCP abuse tests
`security`, `testing`, `priority:p0` · Depends on: 9
- [ ] A server that changes a description or adds a tool after start-up is not honoured;
      a server returning non-text, oversized or injected output is contained; an
      unreachable server fails start-up of that server only, with a logged reason.
- [ ] A user without the scope cannot call the tool (`authorization_denied` audit).

### 11. Approvals wiring
`architecture`, `security`, `state`, `priority:p0` · Depends on: 7
- [ ] `HumanInTheLoopMiddleware` configured from the registry, `approve`/`reject` only;
      the agent is compiled with `checkpointer=None` and has no gated tools when
      `APP_CHECKPOINTER=none`.
- [ ] Tests: approve runs the tool exactly once; reject runs it zero times (the research
      spike showed `checkpointer=False` loses it silently); history, export and summary
      routes still show only user turns and final answers.
- [ ] A resumed run counts each model call's tokens once; `call_agent` has no
      non-idempotent step before the agent call.
- [ ] ADR 0005 decision 3 marked superseded.

### 12. Approval API
`security`, `auth`, `priority:p0` · Depends on: 11
- [ ] `invoke` returns `200 status: approval_required` with the pending action in full;
      `POST /v1/threads/{id}/approvals/{approval_id}` (`approve`/`reject`, scope
      `agent:approve`) is a new run with its own lease, rate limit, budget and timeout.
- [ ] Missing, foreign and already-decided approvals are the same `404`; a new message on
      a pending thread is `409 approval_pending`; the BOLA matrix covers the route.
- [ ] Audit `approval_requested` and `approval_decided`; OpenAPI, README and SECURITY.md updated.

### 13. Approval over streaming
